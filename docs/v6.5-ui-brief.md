# BRIEF — v6.5 UI pass: the last of the ghost, then the payment card

Written 2026-09-21. Hand this to Codex whole. Source discussion lives in
`docs/v6.4-runway.md` and `docs/v6.5-readiness.md`; the visual reference is
Jet's PaymentCard canvas (fourteen artboards, including a live one).

House rules from `docs/v6.5-brief.md` apply unchanged: pure units first,
four languages on every string, money paths strict, and tests that fail
against today's code.

**Order is not optional. Part A before Part B.** Part A changes the
predicates Part B renders, and A is what stops a screen offering money that
does not exist. Do not start B until A's tests are green.

# PART A — a saved summary must never impersonate a settled trade

## What is established

`scripts/inspect-trade-relays.ts` now replays a relay-held chain through the
real parser and the real reducer. Two trades, run 2026-09-21:

```
sm_mtnxzb5y_zpepqcpj          sm_mtg30bzc_18bbyvpg
  CREATE  → CREATED             CREATE  → CREATED
  JOIN    → CREATED             JOIN ×5 → CREATED
  CANCEL  → EXPIRED             LOCK    → LOCKED (lockedAt 1788126927)
  (no LOCK, ever)               (healthy)
```

The first trade never locked. Its sats never entered escrow. Yet on the
buyer's device it rendered **"Ready to claim · Refunded — your sats are
back"** over a ₿2,000 Claim button, and the escrow pill counted those sats
as committed. That state came from the device's saved summary, not from a
replay — the same fallback whose toast reads "the summary here is what's
saved locally".

`EVENT_KIND_TRANSITIONS` reaches APPROVED only from LOCKED. So a summary
that says APPROVED is asserting a LOCK. It may be lying, and here it was.

Shipped already (2026-09-21, uncommitted): `hasLockEvidence` in
`src/ui/decisions.ts`, required by `activeCommittedMsats`,
`sumActiveBuyerSellerTradeMsats` and `isLiveBuyerSellerCommitment`. The
witness is a LOCK in `eventChain` **or** `lock.lockedAt` — not `notesHash`,
which an on-chain lock leaves empty by construction.

## A1 — provenance on the state, and copy that admits it

**Pure unit:** `stateProvenance(state) → "replayed" | "summary"`.

An `EscrowState` must carry how it was built. A state assembled from the
saved summary because replay failed is not the same object as one the
reducer produced, and every surface that spends or promises money needs to
tell them apart.

**Acceptance**

- `EscrowState` carries provenance, set where the summary fallback is built
  and where a successful replay returns.
- The trade card for a summary-only state leads with what it is: this is
  what this device saved, the history could not be rebuilt here, it may
  rebuild on a device that holds the full chain. It does **not** render an
  outcome sentence ("Refunded — your sats are back") as though settled.
- A test builds a summary-only APPROVED state and asserts the outcome
  sentence is absent. Fails against today's code.
- Four languages.

## A2 — no claim without a lock

The Claim affordance asks the same witness the pill now asks.

**Acceptance**

- A summary-only APPROVED state, and any state failing `hasLockEvidence`,
  renders no Claim button and no "your sats are ready" line.
- Instead it offers the only honest action: re-broadcast, and the trade id
  to hand the other party.
- A test asserts a claim CTA never appears without lock evidence. Fails
  against today's code.
- The trade stays fully visible and readable. This gates money, not history.

## A3 — extract `src/ui/me-trade-filters.ts`

`isLiveTrade`, `isOpenListing`, `isDoneTrade`, `filterMeTrades` and
`buildMeTradeCounts` live inside `MeScreen.tsx` where no node test reaches
them. Two regressions in one night came from that, and both shipped
untested.

**Acceptance**

- Moved out verbatim, imported back, no behaviour change.
- **The partition invariant**: for any set of trades, every trade appears in
  at least one of live / listings / done. An earlier attempt made five
  trades reachable only under "All"; this assertion is what catches that.
- Counts equal the length of what the same filter renders.

## A4 — the pill may never quote a trade the tab cannot show

The headline reads from `myTrades` now, same as Me. Freeze it.

**Acceptance**

- A test asserts: if `countActiveBuyerSellerCommitments > 0` for a set, at
  least one trade in that set passes the Live filter. A number the user
  cannot tap through to is the bug this closes.
- A second asserts `activeCommittedMsats > 0 ⇒ count > 0`. The
  `Math.max(1, …)` clamp in `decideChamaBarLabel` exists because those two
  once disagreed; with the assertion in place the clamp becomes belt rather
  than mechanism. Leave the clamp, add the test.

**Open, reported 2026-09-21 afternoon:** the ₿2,000 pill reappeared on
Bestie unprompted and taps to an empty Live tab. All three headline paths go
through `isLiveBuyerSellerCommitment`, which requires lock evidence, so
either that device is running a stale bundle or something re-hydrates the
trade into a lock-shaped state. A4's assertions are the net; if they pass
and the pill still returns, the fault is in hydration, not display.

# PART B — the payment card

Visual reference: the canvas. Every number below is measured from it.

## B1 — `PaymentCard`

One component for the four QR surfaces: atomic funding, on-chain deposit,
claim payout, fund wallet. Fixed regions in fixed places — rail control,
amount, body, status, helper, details — so the card never resizes when a
state changes under the user's thumb.

**The amount is the headline.** Today the awaiting-payment phase of
`AtomicFundingModal` shows no amount at all: it was on the previous phase
and vanished on the screen where money actually leaves. Use `TradeAmount`,
so tapping flips sats ↔ local money.

**Acceptance**

- Card height does not change between waiting, detected and confirming.
- On-chain shows what you must SEND as the headline (amount + peg-in fee),
  with trade amount, fee and total broken out in the expanded details.
- Status region carries the 6.4.6 custody states: waiting, rejected with the
  relay's own words, custody expired.
- Four languages; verify at 320px in Swahili and French, not only English.

## B2 — rail control, from `PagerPills`

Extend `src/ui/screens/tradedetail/PagerPills.tsx`; do not fork it. It needs
an optional icon slot and a way to suppress the chevrons.

- 999px track, sliding indicator of `T.card` + `T.borderHi` with the
  `0 1px 0 #0006` lip, `transform .24s cubic-bezier(.4,0,.2,1)`, labels
  `T.sans` 12/700 crossfading muted → text over `.2s`.
- **No chevrons here.** On the trade view they teach a swipe and swiping is
  free; here a swipe would mint a new invoice and, on-chain, change what you
  owe.
- **Lightning is the default segment for both lock and claim.**
- Emoji, not stroke icons: bolt, chain links, peanut. They carry no stroke
  colour, so selection reads through opacity (1 selected, .5 otherwise)
  while the label crossfades.
- Switching rail with a live invoice asks once, naming both costs: the
  invoice on screen stops working, and the amount may change. A fresh card
  switches silently.

## B3 — `QRCode.tsx`

- **Default `margin` to 4.** `BondCeremonyModal` passes none, so at size 180
  the 12px plate radius clips real modules today.
- Replace the four bordered `<span>` corners with one inline `<svg>` of four
  stroked paths: 36px arms, 16px corner radius, 2.5px stroke,
  `stroke-linecap`/`linejoin` round. CSS borders cannot round a cap, which
  is most of why the old ones looked blunt.
- **No shell surface.** The `rgba(10,10,10,.30)` wash drew a second ring
  outside the code — cyan fading to black — that read as a border nobody
  designed. The frame is the four corners; the outer edge is the card.
- Clearance band 22px so the brackets never cross the code.
- Glow and any remaining bloom come from `T`, not hardcoded: the old values
  were dark-mode only and put a smudge on paper.
- Corner palette: **BRAND · AS SHIPPED — decided, do not change.** Top-left
  `#F7931A`, top-right `#2EE6D6`, bottom-left `#BF5AF2`, bottom-right
  `#F7931A`. These are the values already in `QRCode.tsx`; the three cooler
  candidates on the QR corners boards were considered and rejected.

  The reason is the diagonal: orange at top-left and bottom-right sandwiches
  the code in the sats colour, tying the frame to the amount directly above
  it, while teal and purple hold the other two corners (Jet, 2026-09-21).
  They are brand, not theme — identical in dark and light. Only the shell
  and the glow become theme-aware; the corners never do.
- A `logo` prop taking `"static" | "motion"`: during crediting the island
  runs the v7 boot mark. Reuse `ChamaLoader` rather than a bare `<img>` so
  `prefers-reduced-motion` comes along.

## B4 — tap to copy

The chip is the copy target. On tap a sheen crosses it, a warm ring blooms
from the edge and fades, the label becomes "Copied" and the icon a check,
settling back after ~1.6s. No toast — a toast lands on top of the QR the
user is still looking at. Respect `prefers-reduced-motion`.

Truncate a BOLT11 in the middle. Show a BTC address whole, or first-and-last
six; an ambiguous address is a money bug.

## B5 — the button system

Four tiers, and the tier carries meaning. All 999px radius with the pill
family's 1px lip. Depth is an inset top highlight, a hairline darker border,
a tight contact shadow and one soft ambient shadow; pressing drops 1px and
collapses the ambient shadow.

- **Primary, filled** — only where money moves. Claim your sats (accent),
  Lock with ecash (teal).
- **Raised** — card gradient, same lip: Open Fedi, Copy invoice.
- **Quiet** — border only, nothing at stake.
- **Paired** — the asymmetric pair: Keep Lightning quiet, Switch filled,
  because only one of them costs an invoice.
- Disabled loses the shadow and desaturates.

Touch targets ≥44px. Focus ring visible.

## B6 — handing off, in the right direction

- **Locking** keeps the paste. A note must be minted in Fedi; Chama cannot
  initiate it, and the round trip is the mechanism, not friction.
- **Claiming** hands off: `fediEcashLink` (shipped) opens Fedi with the note
  loaded. Token in the URL fragment, never a query string.
- **"Open with" on every rail**, not a Fedi-specific button: the platform
  share sheet for a BOLT11 and a BIP21 on-chain URI, so any wallet can catch
  it. Offer it only where the platform advertises the capability.

## B7 — the parties, and the arbiter

The trade view shows buyer and seller. **Add the arbiter.** Tapping any
party opens an overlay (`OverlaySheet`) with what a trader needs before
trusting them, and for the arbiter the record that matters: signed conduct
this device has observed, via `arbiterRecord`. No history means unknown,
never good — that rule is already written and must not soften here.

Read-only. Four languages.
