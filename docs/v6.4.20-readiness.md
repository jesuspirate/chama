## One acceptance pass — Jet runs this once

Follow the .22 brief's device policy: no ad-hoc Pixel requests. Use this release
candidate on desktop and Pixel for one collected pass with Jet present. The
candidate must contain this branch's commits; an installed 6.4.19 APK does not.
Record the candidate commit, desktop browser, Pixel app build and result here.
Use simulated/read-only test trades; no funding or voting is needed.

Repeat the four checks on **both Pixel and desktop**:

1. **Notification:** tap a trade notification. It opens the intended trade,
   creator and terms. Pixel covers its native notification deep link; desktop
   covers an enabled browser/PWA notification. Check that the opening link
   carries the correct creator where applicable.
2. **Creator link:** open `?trade=<id>&by=<creator-hex-pubkey>` on a fresh reader.
   It selects that creator's signed listing, with the intended participants and
   amount. Open the same trade again to check the creator is retained.
3. **Plain link:** open `?trade=<id>` without `&by=`. An unambiguous listing opens;
   a trade whose creator is already established on this device retains it.
4. **Conflict:** on a fresh reader that has no creator record, open an old-format
   id with CREATEs from two different accounts, without `&by=`. It refuses both
   and displays: “Two different accounts have published a listing under this
   trade's id, so Chama can't tell which one is real and won't open either. Ask
   the person who sent it for a fresh link.” Then open the genuine creator's
   link and verify the real listing opens. Use a fresh browser/profile for the
   conflict check; clearing a funded wallet or account is not a test prerequisite.
