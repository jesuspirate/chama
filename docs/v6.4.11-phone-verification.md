## B — diagnosis before implementation (2026-09-27)

The VPS service is active at `/home/satoshi/chama-webpush-watcher`.
Public `/health`: HTTP 200, 8 endpoints, 22 tags, 1 configured relay.
Malformed `/register`: HTTP 400. The protected registration store contains one
UnifiedPush registration with host `ntfy.sh` and two opaque tags. No endpoint
capabilities or tags were printed. This proves acceptance, not ownership by a
particular phone or successful last-mile delivery.

Android Force stop suppresses delivery until the user interacts with the app
again; swiping from recents is different. ntfy needs battery optimisation off.
Instant delivery should be enabled where offered; F-Droid always uses it and
hides the switch. Sources: https://developer.android.com/about/versions/15/behavior-changes-all
and https://docs.ntfy.sh/subscribe/phone/.

The new native Settings test requires a matching random nonce to return through
the receiver within 30 seconds. HTTP acceptance alone is not success. The VPS
accepts tests only for an existing, unexpired subscription with matching
capabilities, with a 30-second per-endpoint cooldown and the existing IP limiter.
No trade identifiers/content or identity keys go to the VPS.

Validation: TypeScript typecheck, watcher wake-policy suite, and Android
`:app:testDebugUnitTest` pass. Physical phone receipt remains a device test.
