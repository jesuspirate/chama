# Brief — make on-chain testable in sim mode

Jet, 2026-09-22: on-chain has never been exercised by a human, and there is
no way to rehearse it without real coins and a real wait.

Author: Claude. Verified against `dd0f843d` (v6.4.7).

## What sim gives you today, and why it proves nothing

`src/sim/sim-wallet.ts` has an `onchain` block, and its own comment is honest
about the state of it: *"The deposit-side methods are stubs (sim funding is
via the LN invoice); they exist only to satisfy the interface."*

Concretely:

| Method | Sim returns | Consequence |
| --- | --- | --- |
| `getInfo` | `finalityDelay: 0`, `pegInFeeSats: 0`, `pegOutFeeSats: 0`, `minimumDepositSats: 0` | No minimum, no fee, no wait |
| `createDepositAddress` | `bcrt1qsim…`, `finalityDelay: 0` | Address appears instantly |
| `awaitDeposit` | `{ status: "confirmed" }` immediately | Never shows waiting or confirming |
| `getWithdrawFees` | `feesSats: 0`, `total === amount` | Fee breakdown renders as zeros |
| `withdraw` | `status: "confirmed"`, `feesSats: 0` | Payout never pends |

So every on-chain behaviour 6.4.7 added or changed — the send total with its
fee broken out, the stable waiting/confirming geometry, the minimum-deposit
guard, the "an address has been issued, no new rail" state — is invisible in
sim. A sim run today can pass while the real path is broken.

## Build

Make the sim on-chain leg behave like a slow, expensive chain by default, and
give it knobs so a tester can reach each state deliberately.

### 1. Realistic numbers

`getInfo` returns values in the shape of a real federation: a non-zero
`finalityDelay` (a federation typically waits several blocks), a non-zero
`pegInFeeSats` and `pegOutFeeSats`, and a `minimumDepositSats` large enough
that a small test amount is refused. Pick numbers from the federation Chama
actually uses rather than inventing round ones, and write the source in a
comment so they can be corrected later.

`getWithdrawFees` returns `amountSats + feesSats` as the total, so the
on-chain send-total line has something real to display.

### 2. A deposit that takes time

`awaitDeposit` walks the real states with real gaps instead of returning
confirmed: pending → seen in mempool → confirming (n of m) → confirmed. Use
the same `simDelay()` discipline as the rest of the file so timings stay
consistent with the LN leg.

### 3. Knobs, on the sim URL

Sim mode's public entry point is `?sim=1` (`src/sim/simMode.ts` — there is no
UI toggle, deliberately). Extend that, not a new mechanism:

- `?sim=1&onchain=slow` — the default above.
- `?sim=1&onchain=instant` — today's behaviour, kept so existing sim demos
  and any test relying on instant confirmation do not break.
- `?sim=1&onchain=stuck` — deposit never confirms. This is the state nobody
  has ever looked at and the one most likely to be wrong.
- `?sim=1&onchain=underpaid` — a deposit below `minimumDepositSats` arrives.

Document them in the header comment of `simMode.ts` alongside `?sim=` and
`?testnet=`, since that comment is where the flags are discoverable.

### 4. Keep the partition intact

`src/sim/sim-partition.ts` exists to stop sim trades leaking into real
history, and 6.4.5 fixed a leak there. Nothing in this brief may widen that
boundary — a sim on-chain deposit is still a sim trade. Add a partition test
if the new states touch anything persisted.

## Tests

- Each knob reaches its state, asserted on the wallet interface, not the DOM.
- `underpaid` refuses with a named error the UI can render, not a generic throw.
- `stuck` leaves the funding card in its waiting state indefinitely without
  spinning the CPU or firing a timer after cleanup — `cleanup()` already
  cancels pending invoice timers; the deposit walker must respect it too.
- The sim partition test still passes.

## Then extend the browser check

`scripts/verify-payment-card.mjs` already drives the funding card. Add the
on-chain rail at `slow` and `stuck`: assert the send total and fee line are
present and non-zero, that the waiting geometry does not shift as states
advance, and that once an address is issued the card does not offer a new
rail.

## What NOT to do

- Do not make sim on-chain reach a real chain, testnet or otherwise. Sim's
  contract is that no real money and no external dependency is involved.
- Do not change the real `onchain` path to make the sim easier to write.
- Do not remove the instant mode.

## Verification

`npm run typecheck`, `npm test`, `npm run build`, then `npm run dev` and walk
`?sim=1&onchain=slow` through a full fund-and-lock by hand — the point of the
exercise is that a human can finally see it.
