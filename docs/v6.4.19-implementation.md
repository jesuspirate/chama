## Reader compatibility

The non-locker's RELEASE and locker's REFUND open at the same offset:
`min(committed grace clamped to four hours, half the remaining life)` after
the committed vote timestamp. The anchor uses the existing expiry-plus-slack
ceiling. A second principal vote returns control to the existing two-sided
clock. This adds neither an automatic outcome nor an automatic vote.

A pre-6.4.19 clock has no locker-REFUND anchor. Its unchanged ordering gate
returns `ARBITER_TOO_EARLY` for the same in-window arbiter vote; the old reader retains an unresolved prefix even when new readers have
settled the trade. The reader must update to converge. The regression runner compiles that legacy clock into the
unchanged reducer gate and verifies the error, alongside the new reader's
REFUND resolution. Consequently the principal UI door and wake copy must wait
for reader deployment; they are not shipped here.
