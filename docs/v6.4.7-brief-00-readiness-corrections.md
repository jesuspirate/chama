# Brief 00 — correct the record before anyone reads it as evidence

Do this one FIRST, before any code in 6.4.7. It is small, it is documentation
only, and it removes a false conclusion about money from the document that
gates the rotation flags.

Author: Claude. Verified against `bb3d4091`.

## Why this is not cosmetic

`docs/v6.5-readiness.md` is the release gate. Row 1 of its precondition table,
and the whole narrative under "The blocking trade, measured — 2026-09-21",
currently assert:

> its LOCK was signed and is held in the buyer's local cache, but reached no
> relay we can read

and

> A rebuild that ignored exactly one event … and still reached a claimable
> terminal state therefore **replayed a chain containing a LOCK**, served from
> that device's local cache.

**Both are false.** Pass 3 of `scripts/inspect-trade-relays.ts` replays the
relay-held chain through the real parser and reducer, and the result is:

```
CREATE  → CREATED
JOIN    → CREATED
CANCEL  → EXPIRED
```

No LOCK at any point. `lock.lockedAt` is never set. There is no LOCK on any
relay, no event references one, and no device replay produces one.

The screenshot that supposedly disproved the original finding — *"Your 2,000
sats are ready"* with a live Claim — was **not a replay**. It was painted from
the saved local summary, which is precisely the summary-provenance defect
Part A of the v6.5 UI brief was built to close (`v6.5-ui-implementation.md`:
"Unmarked legacy states are conservatively treated as summaries by the claim
UI"). A rendered card is not evidence of a chain.

So the sequence to record honestly is: the first conclusion (no LOCK was ever
signed) was correct; the revision that overturned it was wrong, and it was
wrong because it reasoned from a UI surface instead of executing the replay;
the third pass, which executed it, restored the first answer with proof.
