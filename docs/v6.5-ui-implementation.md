## Necessary departure from B2

The current wallet API has no invoice cancellation operation. Aborting
`runFundAndLock` only stops the receive watcher; it does not invalidate an
already issued BOLT11. Saying “the invoice stops working” or immediately
starting a competing funding run would be unsafe.

Fresh-card rail changes are immediate. While a Lightning invoice is live,
requesting another rail shows why switching must wait; Switch remains disabled
until the funding operation reports expiry. Once payment is detected or an
on-chain address is issued, the card does not offer a new funding rail. Instant
live-invoice switching requires a backend cancellation guarantee and is not
implemented in this pass.

## Browser verification

Start `npm run dev`, then run `node scripts/verify-payment-card.mjs`.
Set `CHAMA_BROWSER` to a Chromium executable and `CHAMA_PREVIEW` to a different
local preview URL if needed. The fixtures use synthetic, non-payable values
and stub all payment actions.

The browser check covers French and Swahili at 320px in dark and light themes,
stable waiting/confirming geometry, copy feedback, reduced motion, the live
invoice switch guard, the actual atomic/wallet/ecash modals, and on-chain
send-total/fee disclosure. It decodes a screenshot of the rendered 180px QR,
including its rounded plate and logo, and verifies all four brand colours.
Screenshots are written under `/tmp/chama-payment-*.png`.
