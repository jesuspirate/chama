# Brief 08 verification

## A — On-chain attention

The bar/queue selector and notification decision share `onchainAttention`.
Required signatures are checked cryptographically, including dispute signatures;
an asserted signer role cannot hide an outstanding action. Settlement messages
now count as notification activity even when APPROVED does not change.

A device-only observer checks loaded participant trades every 30 seconds outside
the room. It checks deposits, refund maturity and actual spends of every final
transaction input. It never changes replay state. A COMPLETE event does not mean
Bitcoin confirmed the payout. Payment wording is withheld until the deposit and
remaining counterpayment window have been verified. Pending deposits do not ask
the funder to send twice; an insufficient deposit remains actionable.

Current on-chain actions catch up after participant hydration, with the existing
identity-scoped, persisted notification tags and permission/mute gates. Failed
notification delivery is retryable. This covers the native Capacitor/Tauri and
browser delivery paths. Settlement events already carry encrypted pairwise wake
tags and the background watcher subscribes to their kind (38114). No watcher
plaintext or private trade terms were added. When the app is fully stopped,
chain-only changes (confirmation/refund height) are detected on reopening; the
existing opaque relay push wakes for participant events, not Bitcoin blocks.
OS permission, background subscription and actual device receipt still require
a two-device run; no real notifications or payments were sent in this verification.

Regression coverage: `onchain-attention.tests.ts` covers deposit, confirmed lock,
counterpayment, payment confirmation, winner choice, both signature roles on coop
and dispute paths, forged signature metadata, verified broadcast/confirmation,
refund, outsiders, repeated transitions and settlement activity timestamps.

The canonical bar skill is `.agents/skills/chama-bar/SKILL.md`, which Codex
repository discovery scans. The original docs path is a symlink to that file;
AGENTS points at the canonical path. There is only one copy to maintain.

## B — Explorer availability

Transport failures have a distinct error type. The shared guided/classic controls
retry checks at 5, 10, 20, then 30 seconds, cancel retries on unmount or changed
proposal, and keep signing unavailable until a fresh checklist passes. Retry
never chooses a destination or signs. The existing idempotent settlement
finalizer can recheck/adopt/rebroadcast its already-authorized transaction.
Actual checklist mismatches retain the red warning.

Settlement reads use a 20-second per-host timeout. The shipped mainnet default
hedges to Blockstream and mempool.emzy.de; custom explorers and signet remain
isolated. Failed hosts are logged. The failure link in both layouts opens
Me → Advanced → Block explorer, with network verification before saving and a
restore-defaults action.

Verified: typecheck; explorer retry tests (three hosts, all-host failure,
custom/signet isolation, capped backoff, non-retryable mismatch, stale cleanup);
isolated browser test in both layouts (timeout is not red, sign unavailable,
automatic recovery, manual Check settlement retries, settings link). Browser
requests are local/mocked; this does not claim to reproduce Bestie's network.
The full repository suite passed after A.

## C — Syncing in the bar and loader quality

The bar now follows unreachable → needs-you → stranded → in-trade → syncing
→ ready. Known actions are not hidden by initial hydration, and on-chain users
can see them without joining a federation. Only `myTradesLoading` drives syncing;
a public-listing refresh cannot replace the status. Browse's extra initial-sync
indicator is removed.

The old tiny animated boot PNG is replaced in ChamaLoader with an inline vector
dot/orbit, continuously animated with CSS, with static reduced-motion support.
It needs no image request and stays sharp on high-density screens. The bar uses
an 18px version with the existing translated “Syncing…” label.

Coverage: pure bar priority and renderer tests, absence of the Browse-local
indicator, phone browser rendering at 3× pixel density, computed animation and
reduced-motion checks, and disappearance after initial sync while public refresh
continues. Screenshot: `/tmp/chama-brief08-sync.png` (local verification artifact).

## D — Global explicit Browse order

Cheapest and Newest now render a single ordered list across all visible verticals
and routes, without a second category/rail grouping that would undo the order.
Cards retain their category badges, route styling, community chips and actions.
Local/all, own-listing and search filters still apply before ordering. The
existing price-ranking rule is preserved; this change fixes presentation order.
Default restores the grouped view. Existing explicit saved choices survive and
remain scoped to the current identity.

Verified by rendering the actual Browse screen and by clicking all three order
controls in a browser: one listing per category, an offer on another route,
expected cheapest/newest sequences, category badges, local filtering, return to
groups and identity isolation. Typecheck and production build passed (existing
large-bundle warning). The isolated browser suite also passed all money-control,
retry and loader regressions with external requests blocked.

## Final review

A partial deposit now asks only for the missing sats. Before any chain observation,
the funder is asked to check the deposit rather than being told to send again.
A full pending deposit stays quiet. A payout with both valid signatures but no
observed broadcast remains actionable, covering a crash between signing and
broadcasting. Regression cases exercise both cooperative and dispute paths.

Broadcast requests also have the 20-second deadline. Transport errors and server
failures remain retryable, while explicit node rejections (such as an immature
refund) retain their actual reason and are not mislabeled as explorer downtime.
The arbiter commitment boundary is unchanged: being listed in a community pool
alone does not summon a person to a current obligation.

The final suite's old priority-matrix assertion was updated to the brief's new
stranded-before-in-trade order. No application behavior was relaxed to satisfy it.

Final checks passed: `npm run typecheck`, `npm test` (core: 4,219/4,219,
plus the independent suites), `npm run build`, `npm run repo:hygiene`, and
`scripts/verify-guided-onchain.ts` against an isolated browser. Final follow-up
cases also render the real trade controls for sent versus confirmed payouts.
The build reports the existing large-chunk warning. No real coins moved, no
notification was sent to another person, and nothing was pushed or shipped.
