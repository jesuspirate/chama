# JOIN/CHAT wake repair and watcher deployment

JOIN now includes the known participant keys and listing community. CHAT
includes participant keys. The existing ECDH tagger therefore emits one pair
watch per other named participant, regardless of the sender's alerts preference.
Pool membership is not used as a participant list. Existing on-chain assigned
arbiter discovery tags are preserved.

With background alerts enabled, CREATE registers the parent listing's community
watch before a first buyer exists. Launch, discovery, enable and resume seed
that watch for this identity's open parent listings. Summary, terminal and
expired listings do not seed it. Community registration also works without
local ECDH; pair registration still requires it.

The watcher now turns parent CREATE and JOIN community tags into opaque wakes.
CHAT/LOCK/settlement and child listings do not generate community wakes.
Existing timestamp freshness, endpoint registration time, collapse, expiry and
transport rules remain in force. Community watches are shared with saved
searches, so a JOIN can wake those subscribers too; receive-side replay can be
silent when nothing needs their attention.

Tests use the actual CREATE/JOIN/CHAT publisher methods and real ECDH signers,
including sender alerts off, first JOIN, seated arbiter, renewal, launch seeding,
wrong identity and expired listing. The watcher integration starts its actual
HTTP/store/WebSocket process with a fake relay and mocked outbound push, sends
a signed JOIN, and verifies a registered community endpoint receives exactly one
opaque wake with no trade details. No live test event or notification was sent.
