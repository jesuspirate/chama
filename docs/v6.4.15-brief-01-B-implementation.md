## Wake replay

All transports now carry matched opaque tags. The snapshot maps them to
trade IDs or public community scopes. Relay reads use an inclusive delta
cursor; only affected trades replay. Missing CREATE roots are fetched for
newly discovered trades. One broken affected chain cannot veto a valid
trade. The native budget is fifteen seconds and each relay read is capped
at ten; sockets and timers close when a complete response wins.

A locally decrypted JOIN names the buyer and finalized amount. CHAT body
envelopes now decrypt with the saved local key and show the message text;
explicit chat mute and own-message suppression remain. A CHAT alone does
not repeat the already-seen JOIN action. Notifications deduplicate by signed
event identity, including queued CHATs older than the previous job's finish.
The worker merges successful reads into its local snapshot without advancing
the global cursor past another trade's queued events. Rate-limited alerts
retry before the snapshot advances.

A community JOIN seeds the new pair's watch while the foreground app stays
closed. This closes a registration gap found in code inspection; it does not
prove which tag originally woke this Pixel. No wallet, signing client, or
bearer-note operation is imported into the wake replay.

## Delivery and diagnostics

The watcher deduplicates identical signed events per endpoint instead of
suppressing distinct same-tag events for five seconds. FCM no longer uses a
shared collapse key. Every send logs only a short tag, transport, result,
and elapsed time. Every UnifiedPush receipt creates a log entry before
policy, including invalid or inactive-lane receipts.

Foreground policy reads a volatile activity STARTED state written by actual
lifecycle callbacks. It no longer waits on the main looper or treats a cold
startup timeout as foreground. The branch (`resumed`, `started`, or
`no activity`) is recorded. The local Alert log retains fifty entries, matched
tags, content-free job outcomes, trade counts, elapsed time, notification IDs,
and the last successful registered tags and registration HTTP result.

Presence renewal CREATEs carry a signed advisory `renewal` tag and stay
silent in the watcher and both foreground/native listing selection. New
listings respect the existing preference and category/community gates, name
the seller and amount, and share an Android group with a summary notification.

## Verification and limits

Regression tests use real signed CREATE/JOIN/CHAT events, local encryption,
a sixty-trade snapshot, a broken unrelated chain, a broken affected chain,
community-to-peer watch learning, identity mismatch, queued messages,
explicit mute, named/grouped listings, and silent renewal. The watcher runs
against a local relay and mocked transport: a JOIN plus two distinct CHATs
within five seconds produce three wakes; duplicates and renewal stay quiet.
FCM tests verify opaque tags and absence of a collapse key. The required `npm run typecheck`, `npm test` (4,230 engine tests plus
the remaining application suites), and `npm run build` pass. Android Java
compilation and unit tests pass using cached Gradle dependencies.

No production watcher restart, deployment, phone installation, push, or ship
was performed. The physical Pixel cold-process test remains for a future
authorized release. The historical replay exception remains unknown.
