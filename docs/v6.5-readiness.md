initial omission; the relay record does not identify which path sent it.

For an older stuck trade, reopen it on the original locker's device using
6.4.19 and check whether the other participant now sees Locked. A session
that still holds the signed LOCK can republish it; the full trade view also
offers **RE-SEND TO RELAYS · HEAL THIS TRADE** (Re-broadcast).
Updating/restarting alone is not a
guaranteed repair, especially when the LOCK exists only in the disk cache.
If it does not recover, a sim trade can be abandoned and a fresh simulation
started. For a real on-chain trade, preserve the original device and trade
data and use the funder's refund controls when the committed Bitcoin refund
height is reached; do not assume a universal 30-day wall-clock deadline or
that a missing LOCK means the deposit is gone.

## Native push — implemented, deployment and device acceptance open

The Android shell now has a Capacitor push plugin, UnifiedPush connector and FCM
service. Background alerts remain opt-in. Play services plus Firebase configuration
select FCM; otherwise an installed UnifiedPush distributor can be selected through
the system picker. Settings name the transport. No Firebase token is requested
before opt-in. Disabling removes local interests, unregisters the endpoint and
suppresses delivery immediately even when network cleanup fails.

The native store holds only opaque watch tags and endpoint capabilities. Token
rotation re-registers existing interests; foreground resume retries registration.
The VPS supports encrypted UnifiedPush payloads and FCM data-only messages with a
120-second TTL. It independently rejects old, future and pre-registration events,
deduplicates relay deliveries, and permits only trusted push endpoint hosts. Server
credentials never enter the app. Registration uses possession of the opaque endpoint
capability, as the existing Web Push path does; it does not attach a Nostr identity.

A native wake says only “There may be new activity. Open Chama to check.” It never
asserts a payment or outcome, and never opens or operates a wallet in the background.
Opening the app still fetches and verifies escrow state. Foreground native wakes
are suppressed so live notification policy owns that session. This preserves the
existing opaque-wake architecture; it is not a headless signer implementation.

Before deployment, configure the Firebase Android application for `app.chama.market`,
provide its public `android/app/google-services.json` at build time, and configure
`FCM_SERVICE_ACCOUNT_FILE` on the VPS. Existing FCM-less builds remain usable with
UnifiedPush. See `scripts/vps-webpush-watcher/README.md` for endpoint hosts and rollout.
Neither external configuration nor deployment has been performed in this change.

Acceptance still requires a physical no-Play-services device/distributor and a
Play-services device, app closed, with real fresh transitions and historical
replay controls. The user confirmed no existing test setup they could identify.
Nothing here is represented as native push shipped.

## Record and text rules

Arbiter records describe signed conduct in the history this device has observed.
No history means unknown/new, never good. Bonds are verified funds at risk, not
proof of identity or independence. This copy rule is mandatory for trade,
dashboard and roster renderings.

Listing bodies are bounded at 8,000 characters at the wire boundary. React text
nodes render pasted HTML literally. The parser exposes no HTML or image nodes;
HTTP(S) links show their destinations and use noopener/noreferrer/nofollow.
Legacy readers continue to see `description` as the short title.

Avatar uploads are embedded raster only, capped at 48 KiB and 2048 × 2048.
Locally decoded first-frame PNGs provide a reduced-motion fallback. Third-party
picture URLs are not fetched. Profile publishing merges the latest readable
kind-0 document, preserving unrelated fields.
