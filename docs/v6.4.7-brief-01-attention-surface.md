`loudClaims` is a `.map()`, so the red alarm is not one card — it is N. A user
with two stranded notes, a leftover and an exhausted lock recovery meets four
glowing cards and a pill quoting a number that belongs to none of them.

Three ambers on one screen is reachable today. Your law says two is a bug.

## The law to build to

**One LOUD surface per screen, and the chrome owns the channel.** Everything
else is either a quiet row or an item-level badge.

- Colour means state, never importance: **red** = money at risk, **amber** =
  your move, **purple** = money moving, **green** = done.
- The pill is the single live channel. It already has a priority ladder
  (`decisions.ts:1119`): `unreachable > needs-you > in-trade > stranded >
  ready`. Do not build a second ordering next to it.
- Per-item urgency stays on the ITEM. Never repeat a card's badge in chrome.

## What NOT to do

Do not hide money-safety cards. The invariant at `MeScreen.tsx:576`
(`INVARIANT(stranded-notes-surfaced)`) is correct and stays: a bearer note the
drain gave up on gets a persistent, actionable surface, never a console line.
The bug is not that these cards exist — it is that they all shout at once. A
brief that quiets them by collapsing them into an accordion trades a noise bug
for a money bug. Everything reachable today stays reachable.

## Build, in this order

### 1. A pure selector, beside the pill's

New export in `src/ui/decisions.ts`, next to `decideChamaBarLabel` so the two
ladders sit in one file and are read together:

```ts
export type MoneySafetyEntry =
  | { kind: "stranded-claim"; escrowId: string; amountMsats: number }
  | { kind: "unresolved-credit"; … }
  | { kind: "leftover"; … }
  | { kind: "lock-recovery"; … }
  | { kind: "pending-ecash-export"; … };

export function selectMoneySafetyFocus(entries: MoneySafetyEntry[]): {
  focus: MoneySafetyEntry | null;   // the one LOUD card
  quiet: MoneySafetyEntry[];        // everything else, in order
};
```

Pure, no React, no storage reads — same discipline as `decideChamaBarLabel`.
Ranking: money at risk first (`stranded-claim`), then recoverable-and-worth-it
(`leftover` above the dust line, `lock-recovery`), then informational
(`unresolved-credit`, `pending-ecash-export`). Within a kind, larger amount
first, then oldest.

**Invariant, and it is the whole point:** `focus` plus `quiet` must contain
every input entry, exactly once. This is the same reachability law A4
established for the Me filters — a thing that exists must be reachable
somewhere. Write that as an assertion in the tests, not as a comment.

### 2. Render one loud card and one quiet group

`focus` renders as the card it renders today, glow and all. `quiet` renders as
a single bordered group — one header (`T.muted`, mono, uppercase, no fill), one
row per entry with its amount and a chevron, each row tapping into the same
handler its loud card uses today. No glow, no tinted fill, no second header.

A quiet row is not a downgrade in reachability: it is one tap from the same
action, and it is visible without opening anything.

### 3. Stop the hero repeating the pill

`AttentionQueue` already takes `suppressEmptyState` (`AttentionQueue.tsx:43`)
so it does not say "all caught up" above a money action. Extend the same idea:
when the pill is showing `needs-you` with count N, the hero must not render its
own count chip (`AttentionQueue.tsx:125`) with the same N. One number, one
place. The hero keeps its title and its cards; it loses the duplicate badge.

### 4. Audit the shell for double-render

`PendingLockCard` and `PendingPayoutCard` each appear at two call sites in
`App.tsx` (4503/4718 and 4512/4727). Confirm those are mutually exclusive
routes and not two surfaces that can both mount. If they can both mount, that
is a bug of its own and it belongs in this pass.

## Tests

Add `src/ui/attention-surface.tests.ts`, in the style of
`src/ui/escrow-pill.tests.ts`:

- **Partition:** for a fixture set, `focus` + `quiet` equals the input set,
  no duplicates, no drops.
- **At most one loud:** for every fixture combination, exactly zero or one
  entry is `focus`.
- **Two-ambers invariant:** assert the rendered tone of `focus` and the tone of
  the quiet group are never both amber — encode tone as data on the entry so
  this is testable without a DOM.
- **Priority:** a stranded claim outranks a larger leftover. Money at risk
  beats money that is merely waiting.
- **Pill agreement:** when `decideChamaBarLabel` returns `stranded`, `focus`
  is the stranded entry. The two ladders must not disagree about what matters
  most on the same inputs.
