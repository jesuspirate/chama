## Decisions and limits

- `CircleCanvas` is the **creation wizard**, not a second listing browser.
  Circles on Browse use the same filter/results handling as other categories;
  no wizard scroll behavior was changed.
- The engine already kept its broad public CREATE subscription open. It remains
  for the existing notification shade and off-filter counts. The additional
  Browse-owned subscription uses the existing community/category tags. Rail is
  a payload field, with no indexed rail tag or separate rail selector in this
  Browse screen; rail grouping/filtering stays after verified replay. No writer
  tags or settlement rules changed. K separately defers extension-based
  notifications and other background signer work.
- Default grouped Browse inserts at the front **within the existing category/
  settlement group**. Explicit cheapest/newest sorting remains authoritative.
  Buffering applies to new CREATEs, not to legitimate cancellation, stock, or
  participation updates on an existing listing. Space for filter/results
  controls is reserved so an arriving chip or pending pill does not push cards.
- A backup receipt records the user's action, not proof of a recoverable
  password-manager backup. It contains only `1`, keyed by public identity; no
  nsec is stored in the receipt. Failed clipboard writes or rejected save calls
  do not set a receipt. Save & continue never acknowledges backup.
- The two-door chooser replaces the old first-visit teaching screen and setup
  toggles. The existing default newcomer setup and stored-key startup behavior
  remain; teaching and market changes belong after sign-in.
- Signup has no clipboard operation and no auxiliary Copy/Save button. Real
  credential controls remain visible during handoff; submission never posts an
  nsec. The L reminder provides explicit Copy key; the reveal is only under Wallet.
  Copy and supported credential-store Save are explicit actions in Me
  and the unsaved sign-out dialog. Generated-form autofill still requires submit.
- Reveal requests the **active signer**, validates that its key belongs to the
  displayed identity, and never falls back to another account's stored key.
  External signers get an explanation; an unavailable export times out after
  five seconds and does not trap someone trying to sign out.
- **Safety correction to brief F:** do not clear Safari Website Data to cure a
  join error. That may destroy funded wallet state; the identity key is not an
  ecash backup. Preserve the failing state and obtain the captured error first.
  See [Safari evidence](evidence/ios-safari-join.md) for the retry procedure and
  pinned-source iroh fallback finding.

## Federation disclosure and share limits

- Browser inspection uses the existing director for public preview and the active
  matching wallet for `getConfig` / `getMetaConsensusValue(0)`. Anonymous preview
  uses a separate public-preview transport; it never calls createWallet, open,
  join, seed generation, or reset. Previewing another federation cannot claim
  its dynamic limits are known when the browser SDK cannot read its meta module.
- Native `/federation-preview` downloads invite-verified configuration and reads
  consensus metadata directly. It does not obtain a client or touch a wallet DB.
  Older native bridges return unknown information until rebuilt with this route.
- Registrable-domain checks use `tldts` (including private suffixes), not a
  last-two-label shortcut. Repeated iroh node IDs are a signal; distinct iroh
  nodes sharing a relay are not evidence of one guardian operator. These signals
  are advisory, not proof of independence or solvency.
- **Implementation choice:** a new public circle uses its selected count as both
  minimum and maximum. An unlimited circle cannot prove that a payout fits a
  balance ceiling. A preference question was offered; this reversible default
  follows the brief's bounded-payout formula, rather than treating silence as
  approval. Existing committed rotation-round seat terms are retained; new-creation caps
  do not rewrite or prevent settlement of committed circles.
- Missing balance metadata falls back to the invoice ceiling. Missing invoice
  metadata, failed consensus reads, or malformed values give no verified maximum;
  new public creation refuses. BigInt arithmetic rounds the maximum down to whole
  sats. Private circles remain available with guidance. Limits are re-read before
  a new public CREATE, not trusted forever from a displayed card.
- Simulation supplies explicitly synthetic invoice-limit metadata only through
  the sim wallet, avoiding real federation access for this UI. It is not evidence
  of a production federation limit.
- See [the native public-preview check](evidence/federation-custody-preview.md)
  and [the Firefox/Bitwarden experiment](evidence/password-manager-visible-fields.md).
  The control offered Save; the first visible Chama-field trial did not.
  Jet then requested the revised D1 design: visible inputs and Save & continue,
  with explicit confirmation in Me. That newer D1 takes precedence over the
  older addendum’s Copy-only fallback. Manager save prompts remain unverified
  for the final flow; the app never treats submission as a successful backup.
  No dummy login was saved and no nsec was posted.

## Browse community orientation (M)

The device timezone is read locally through Intl. Named zones map to countries
using [IANA zone.tab](https://data.iana.org/time-zones/tzdb/zone.tab) and timezone
aliases; UTC, offset-only, unknown zones, unknown/global communities, and matching
countries show nothing. This is a possible-location hint, never a verified location.
A browser-wide `chama_timezone_nudge_v1:<slug>` receipt records only that the nudge
was shown, so navigation/reload/another identity does not repeat it for that chama.
Not now and Switch also dismiss it. No country, timezone, or key is stored there.

Switch only navigates to Me › Community and expands the suggested country. It
does not select a federation or mutate a wallet. Me still blocks switching during
an active commitment and retains the existing funded-wallet checks. Browse, the
assisted canvas, and the circle creation canvas use the same flag + ISO-3 chip.
ISO-3 codes come from [Unicode CLDR territory aliases](https://github.com/unicode-org/cldr/blob/main/common/supplemental/supplementalMetadata.xml);
the data license is included alongside the table. Country names reuse the existing
Intl-backed country-name helper, now accepting the current interface language.

The UI regression checks emulate Africa/Nairobi with USA: the translated hint,
Not now/reload suppression, Switch preselection with no committed selection,
active-trade blocking, explicit-APK suppression, matching zones/UTC silence, and
all three chip destinations. Generated 390px evidence lives under
`outputs/first-circle-phones/community-*.png` (ignored fixture screenshots).

## Section O — storefront-only bond creation retired (2026-10-04)

The bond ceremony no longer offers a storefront-only checkbox or sends a
`roles` argument. Both automatic announcements for newly funded bonds and
manual announcements use the arbiter default; their payload has no `roles`
field. Merely opening an existing locked merchant bond publishes nothing.

The owner’s dashboard bond card shows the retirement sentence once on the
card, in en/es/fr/sw, while their latest verified announcement is merchant-only.
It does not appear for another owner, an absent/default role, a dual-role bond,
or a superseded merchant declaration. Closing bond management refreshes the
owner’s announcements, so a successful explicit re-announcement removes the
nudge. This is a contextual line, not a dismissible alert or a new global status.

The `BondRole` schema, default, parser, cache role retention, 2,500-sat merchant
listing floor and arbiter-pool exclusion are unchanged. Existing signed opt-outs
are honored until explicitly replaced. Help & FAQ and the bond tip had no
storefront-only copy remaining; the obsolete ceremony strings were removed in
all four languages. Both the A0 schema brief and A2 listing-policy brief now mark
the creation lane retired on 2026-10-04, retaining their historical reader rules.
